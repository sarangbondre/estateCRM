# CR-013: Host on Vercel as one project with Vercel Services (instead of 7 projects)

| | |
|---|---|
| Raised | 2026-09-30, by the product owner (Vercel suggested Services when the repo was imported) |
| Affects | HLD §9/§10 hosting and ADR-0002 (7 Vercel projects), `docs/04-lld/data-hosting.md` (per-project env), provisioning runbook |
| Status | **AWAITING `APPROVED: CR-013`**. Configuration choices confirmed by the product owner on 2026-09-30 (below) |

## What
Deploy all seven apps as **one Vercel project** using Vercel Services (beta, available on Hobby), defined in the root
`vercel.json`:
- **Services:** `web` (Next.js) plus `intake`, `records`, `journeys`, `crm-engine`, `listings` and `insight` (Hono preset, entry
  `services/<svc>/index.ts`). All in region `bom1`, 60 s functions, pnpm 12.7.0.
- **Public routes (top-level rewrites), all other paths internal:**
  - `/public/v1/{listings,projects,demand-posts,changes}…` → listings. The website API: `/public` is stripped by a
    `request.path` transform, and `X-Api-Key` is still required.
  - `/svc/<svc>/internal/v1/{relay,drain/…,jobs/…}` and `/svc/<svc>/health/…` → that service. Supabase pg_cron uses these;
    `/svc/<svc>` is stripped and `X-Cron-Secret` is still required.
  - everything else → web.
- **Bindings** (private calls; Vercel injects the URL; Vercel rejects cycles): web → all six (`SVC_<SERVICE>_URL`); records →
  intake; journeys → records, listings, intake; crm-engine → records, journeys; listings → records; insight → records.
  - Services reach **web** on its public production address (`VERCEL_PROJECT_PRODUCTION_URL`, set by Vercel) for JWKS
    and service tokens, because web → service plus service → web would be a cycle. web's proxy skips `/internal` and
    `/.well-known`.
  - **intake → records** uses the public path `/svc/records/v1/{vocabulary,micromarkets}` (service token required),
    because records → intake is already bound. Found on the first deploy ("circular service binding: web → intake → web").

## Why
- One domain and one deployment: previews include all seven services at the same commit. Internal services are not
  reachable from the internet at all, which is stronger than the 7-project design, where every service had a public URL.
- Simpler provisioning: one project instead of seven.

## Decisions confirmed by the product owner (2026-09-30)
1. Website API path: `/public/v1/…` on the app domain.
2. Scheduler access: `/svc/<service>/internal/…` with the per-service cron secret. The scheduler stays in Supabase pg_cron,
   because Vercel Cron on Hobby runs at most once a day and the event relays need every minute. Revisit at the paid gate.
3. Service names = folder names.
4. Bindings as listed above.

## Impact
- `services/<svc>/vercel.json` and `api/index.ts` are removed; each service has `index.ts` (default export of the composed
  Hono app). The scaffold generator is updated.
- Environment variables are shared across services in one project: only prefixed per-service names are allowed
  (`RECORDS_DATABASE_URL`, …), as the runbook says. data-hosting §3 ("one DATABASE_URL per Vercel project") is superseded
  by this rule.
- Scheduler base URLs become `https://<domain>/svc/<service>` (`configure-environment.mjs` unchanged).
- Risks: Services is in beta. `vercel dev` couldn't start all 7 locally (its dependency installer crashed), so local dev
  stays `pnpm dev`, and the first preview deployment validates the routing. Fallback: 7 separate projects (the previous
  design); the service code is the same, and only config would change.
