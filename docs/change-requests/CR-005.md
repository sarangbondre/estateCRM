# CR-005: Phase 1a pilot on free plans (temporary NFR relaxations)

|---|---|
| Raised | 2026-09-24 |
| Raised by | Sarang Bondre (product owner), during Stage 3 |
| Affects | `docs/02-prd.md` v0.5 (approved) §8 NFRs; HLD ADR-0008 |
| Status | APPROVED 2026-09-24 |

## What
Add PRD §8.4 **"Phase 1a pilot (free plans)"**. Until the paid-plan gate is passed, these NFRs are relaxed:

| NFR | Approved | Pilot value |
|---|---|---|
| NFR-1 Throughput | 1,000 rps | Best effort (free-plan limits) |
| NFR-3 Availability | 99.9% | Best effort; no SLA |
| NFR-4 Backups | PITR | Nightly `pg_dump` per schema; up to 24 h data loss acceptable |
| NFR-5 Bulk | 100k rows ≤ 30 min, 10 files/day | ≤ 20k rows per file, ≤ 3 files/day (DB ≤ 500 MB) |
| NFR-11 Volume | 5M records | ≤ ~200k records in total |
| NFR-17 RPO/RTO | 5 min / 1 h | 24 h / 1 day |
| Data | Real 11 Estates data | **Sample or anonymised data only**; no real client or owner contacts |
| Use | Production | **Internal testing and demo only** (Vercel Hobby is non-commercial) |

**Paid-plan gate:** Vercel Pro, Supabase Pro + PITR (Mumbai), a dedicated Hugging Face endpoint. After that, all approved
NFRs apply again with no further CR.

## Why
The product owner wants free plans everywhere for now (2026-09-24), to build and try the product before spending.

## Impact
- **PRD:** a new §8.4; no other change.
- **HLD:** already designed for it (§10.2, ADR-0008). The design is the same for paid plans.
- **Stage 4:** the capacity plan covers both the pilot and the production sizing.
- **Stage 7:** the final load-test gate runs on paid plans. The pilot can be demonstrated earlier.
- **Risk:** putting real personal data into the pilot would break DPDP safeguards (no backups, non-commercial terms).
  The gate exists to stop that.
