# CR-010: Implementation library deviations

| | |
|---|---|
| Raised | 2026-09-28, Stage 7 (intake, listings) |
| Raised by | Claude (implementation) |
| Status | **APPROVED 2026-09-28: auto-approved (technical)** under B3. |

1. **Intake reads xlsx with its own streaming reader** (`services/intake/src/adapters/xlsx.ts`: zip central directory + node:zlib + streamed sheet XML) instead of exceljs' streaming WorkbookReader. That reader intermittently lost every sheet of small workbooks (about 20% of runs locally), and it can't name sheets written by openpyxl or exceljs. exceljs stays the approved library for **writing** workbooks (exports, synthetic data).
2. **`sharp` for photo renditions (listings).** The LLD wants 1600 px WebP renditions. `sharp` needs its install script allowed in `pnpm-workspace.yaml` `allowBuilds`. Until then, photos are published with metadata stripped (EXIF/XMP/text) but not resized. Proposed: allow `sharp` and add the renditions (a follow-up listings task).
3. **No `btree_gin`** in several services: owner roles can't install extensions, so array filters use plain GIN indexes and the tenant is filtered first. (Records created `btree_gin` in `extensions` with its migrator. At provisioning, either pre-create the extension in the platform bootstrap or keep plain GIN everywhere.)
