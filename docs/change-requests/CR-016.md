# CR-016: Assistant model time limits that the free providers can meet

| | |
|---|---|
| Raised | 2026-10-03, pilot: every question fell back to keyword matching after the Hugging Face token was added |
| Affects | insight LLD §4.2 (2.0 s per attempt, 2.5 s for the model phase), `services/insight/src/config.ts`, `src/adapters/hfPlanner.ts` |
| Status | APPROVED 2026-10-03, auto-approved (technical, questionnaire B3); listed for the product owner's review |

## What happened
After the token was set, the planner calls failed one after another (seen in the logs once error text was logged,
#100–#102):
1. `400 model_not_supported`: Qwen2.5-7B-Instruct is only on featherless-ai, which the account doesn't enable. The default
   became Llama-3.1-8B-Instruct, the LLD's named alternative and intake's default (#103).
2. `405 json_schema response format is not supported` by the provider Hugging Face picked. The planner now retries
   without `response_format` (#104); the prompt asks for one JSON object and the reply is validated.
3. The retry then hit the 2 s attempt limit (aborted after 1,977 ms and 2,003 ms). Every request lands on a fresh
   Vercel instance, so the json_schema refusal costs about 0.7 s each time.

## Decision (implemented)
- `HF_ATTEMPT_MS` (default **5000**) and `HF_BUDGET_MS` (default **6500**), env-configurable.
- The model phase still sits inside the 15 s stream cap. On Vercel the gateway waits 3 s + 6 s cold-start allowance
  (CR-014) for the stream to start.
- Keyword fallback is unchanged when the model is slower than the budget.

## Impact
The p95 target for the chat's first token (PRD) is at risk on free providers. The M7 benchmark and a paid dedicated
endpoint (PRD §8.4 paid-plan gate) remain the way to meet it. No contract, schema or event change.

## Addendum 2026-10-03: model and provider
The Llama 3.1 8B route (Together, chosen by Hugging Face) doesn't support json_schema, and its plain-JSON replies didn't
parse. With the paid Hugging Face key the default is now **`openai/gpt-oss-120b` pinned to the `groq` provider**:
structured output is supported and latency is low, with `reasoning_effort: low` and max_tokens 1000. The new
`HF_PROVIDER` setting (default `groq` only when `HF_MODEL` isn't set) changes the provider; `HF_MODEL` still changes the
model. The M7 benchmark remains the gate for the final choice.

## Addendum 2026-10-03: rate limits
On Hugging Face, Groq runs on a provider-wide organisation shared with other customers (750,000 tokens per minute).
Bursts hit 429 with "try again in 134 ms", and the planner then skipped the model for 60 s. Now it waits for a hint of up
to 1.5 s and retries once, and a rate limit pauses the model for 10 s instead of 60 s.
