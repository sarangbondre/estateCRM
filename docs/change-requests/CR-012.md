# CR-012: Contract and scope gaps needing a product decision

| | |
|---|---|
| Raised | 2026-09-28, Stage 7 (records, journeys, crm-engine) |
| Raised by | Claude (implementation) |
| Status | **OPEN: needs the product owner** (these change a contract's meaning or the upload standard). |

1. **Building name in the upload schema.** Appendix C (the 89 extractor columns) has no building name or floor, so uploaded ads can never reach the "same property" dedup branch. Repost/second-source detection then works only for staff-entered records, which affects the M3/M4 benchmarks. Proposal: add `building_name` (and optionally `floor`) to Appendix C, the IntakeRow schema and both extractors. Owner of the standard: Vinit and Priyanka.
2. **"maybe" proposal feedback** (you said yes to C3): add `maybe` to `ProposalFeedback.feedback` and `proposal.feedback_recorded.v1.verdict`. crm-engine treats it as neutral. The journeys DB already accepts it.
3. **`crm_notes` from uploads** are dropped today (records has no notes table; notes live in journeys). Decide: ignore (current), or route them to journeys notes.
4. **Smaller additive contract items:**
   - `lost_competing` kind in `market_data.recorded.v1`;
   - a place to store `sourcingRequestId` on add-supply;
   - a close reason for expired/paused demands;
   - notification kinds `queue_reassigned`, `proposal_failed`, `demand_touch`;
   - 503 declared on the records photo endpoints;
   - keep `candidates` on idempotent replay of a duplicate-property 409.
