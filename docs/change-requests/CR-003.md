## What
Replace BRD v0.5 with **v0.6**. Journeys, life curve, publication rules, metrics and stack are unchanged. The change is
a **controlled classification vocabulary** that the CRM shares with Vinit's newspaper and WhatsApp extractors.

| Area | v0.5 (approved) | v0.6 (proposed) |
|---|---|---|
| Classification | Supply/Demand + segment + transaction type (Resale / Lease / New project) | One fact per field: **record_scope → deal_type → market → segment → property_type → side** (+ side_evidence) |
| Deal types | Resale, Lease/Rent, New project | **Sale, Lease, JV, Pagdi**. New project = Sale + market Primary; Resale = Sale + Secondary; demand may be Any |
| Segments | Residential, Commercial, Industrial (Land pending OQ-6) | **+ Land** (OQ-6 resolved), with land_use |
| Property types | Free | Controlled list per segment (e.g. Apartment, Studio, Office, Gala, Plot…); BHK as bhk_min / bhk_max |
| Deal tags | Not defined | sale_mode (Auction), deadline_date, tenancy_status (Tenanted = preleased), tenure, agreement_form (Leave and License), is_jodi, possession_status/date, furnishing, price_negotiable |
| Labels | Stored ("Resale, for sale") | **Generated, never stored** ("For Rent", "Wants to Buy, New Project"); filters use stored fields |
| Record scopes | Property only | **+ Business, Capital, Equipment, Market Participant, Market Signal**: stored and viewable in Phase 1 (desks, Archive, Network, Watchlist), with no journeys |
| People | Roles (owner, broker, client…) | **party_type** (Owner, Broker, Developer, Company, Bank, Society, Government), independent of side |
| Intake | Template mapping | **Extractor files in the standard schema**; out-of-list values **rejected row by row**; needs_review rows loaded into a review queue grouped by review_reason (new §4.7) |
| Governance | — | Adding a vocabulary value is a change to the standard, **owned by Vinit and Priyanka**, applied to the CRM and both extractors together |
| Dashboards | Demand / Supply / Data quality | Classification grids (segment × deal_type/market); **Other scopes** (desks, Archive, Network, Watchlist); **Side checks** on data quality |
| Risks | R1–R14 | **+ R15** wrong side |
| Open questions | | OQ-19 extended to Industrial, Land, JV and Pagdi; OQ-10 extended to who works the desks and Watchlist; new OQ-25 (hotels under Commercial), OQ-26 (1 RK = 0.5 BHK Studio), OQ-27 (Pagdi kept) |

## Why
Vinit standardised the deal vocabulary on 2026-09-24 so the CRM, the newspaper extractor and the WhatsApp extractor all
store the same fields and values. This removes ambiguous labels and legacy terms.

## Impact on later stages
- **Stage 1:** `docs/01-brd.md` becomes v0.6. The PDF is rebuilt.
- **Stage 2:** PRD v0.4 → **v0.5**:
  - Information model: deal_type, market, property_type, bhk, deal tags, party_type, record_scope, and the new BIZ/CAP/EQP/WCH records.
  - Quick add and Add supply forms follow the classification order with controlled dropdowns.
  - Generated labels everywhere.
  - Matching on the shared fields and deal tags.
  - New list views: Business Desk, Capital Desk, Archive, Network, Watchlist.
  - Review queue grouped by review_reason.
  - Dashboards: classification grids, other scopes, side checks.
  - Two intake modes.
  - Field dictionary (Appendix C).
  - Prototype updated.
  - A new `APPROVED: Stage 2` is needed.
- **Stages 3–7:** not started. The HLD will likely treat the **vocabulary / reference-data service** and the **non-property
  desks** as part of an existing service rather than new ones (decided in Stage 3).
