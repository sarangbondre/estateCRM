# CR-017: Assistant planner: keywords first, model for the rest

| | |
|---|---|
| Raised | 2026-10-03, after the live M7 benchmark |
| Affects | insight LLD §4.1 (the order: shortcut → model → keyword fallback) and §4.5, `services/insight/src/application/chat.ts`, `src/domain/plans/keywordParser.ts` |
| Status | **Decided by the product owner on 2026-10-03 ("go with option 1") and implemented.** Formal `APPROVED: CR-017` pending |

## What happened
The live M7 run (PRD Appendix A, 13 questions) with the real model (`openai/gpt-oss-120b` on Groq) scored **7/13 = 54%**,
below the 85% target. The model picked the wrong plan (count instead of list) or missed filters. The keyword parser alone
scored **13/13**.

## Decision
1. The keyword parser runs first. Its decision is used without calling the model when:
   - it recognised the question,
   - its plan validates, and
   - the question isn't asking for something a generic offer/demand list or count can't express: rankings, breakdowns,
     comparisons or trends ("which localities have the most…", "by BHK", "compare…").
2. Dedicated intents always stay on keywords: gap, prices, sources, agents, bundles, follow-ups, uploads, queue.
3. Everything else goes to the model as before. If the model is unavailable, or its plan doesn't run, the keyword parser
   is the fallback and the notice says so (#107).
4. A keyword-first answer has `model: null` and `fallbackUsed: false` (no fallback happened).

## Consequences
- The benchmark is 13/13 on every run, and those answers make no model call: faster, no tokens, no rate limits.
- Open-ended or analytic questions still use the model. The model choice can still change with `HF_MODEL` /
  `HF_PROVIDER` (CR-016).
- Tests: `tests/chat.int.test.ts` covers both routes (a "Compare: …" phrasing reaches the model), and the benchmark
  asserts that no Appendix A question needs the model.
