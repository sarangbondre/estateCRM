## What
Replace the approved BRD v0.3 with the client's **BRD v0.5**, in full. Main changes:

| Area | v0.3 (approved) | v0.5 (proposed) |
|---|---|---|
| Company | 11estate | **11 Estates** |
| Users | Operator, broker, manager | **Demand team** and **supply team**, plus owner/manager and data operator |
| Data model | Listing (Supply/Demand), Contact, Sighting | **Property, Project, Offer, Demand, Person (roles), Enquiry, Touch, Match, Sourcing request, Proposal, Site visit, Deal**, market data point |
| Transaction types | Sale / Rent / Lease | **Resale, Lease/Rent, New project** |
| Source types | Source name only | **Channel / Digi / Direct**, with capture mode stored separately; first touch gets the credit |
| Status | Active / Expired / Closed | **Independent axes:** Record, Publication, Commercial, Signals (supply); Record, Publication, Commercial, Exits (demand) |
| Freshness | Expiry after N days (PRD A-28) | **Life curve** Fresh → Ageing → Stale → Expired, thresholds per category, automatic actions |
| Publishing | Published / not (PRD: manual approval) | **Private / Anonymous / Public** ceiling rules; the team chooses within the ceiling; MahaRERA numbers on every listing |
| Website location | Locality (+ building and landmark per CR-001) | **Locality only.** Building names only in proposals to qualified clients |
| Work process | Not covered | **Supply journey** (Must call / Should call, daily capacity, call outcomes) and **demand journey** (understand, qualify, sourcing, proposal, site visit, In process, Closed; exits Lost / Dormant / Invalid) |
| Matching | 1:1, scored | **Many to many, bundles, date aware**, micromarket hierarchy, built up vs carpet like with like, close/price-change propagation |
| Entry | File upload only | **File upload + manual entry** (quick add, Add supply, updates after calls and visits) |
| Scope added | | Deals to Closed, Enquiry, proposals, site visits, project microsites, anonymous demand posts, data quality dashboard |
| Scope removed/out | | Commissions/accounting; new project registration/empanelment/booking-to-payout |
| Metrics | M1–M9 | Unchanged |
| New risks | | R10 upload lag, R11 team bandwidth, R12 attribution disputes, R13 follow-up gaps, R14 RERA compliance |

## Why
11 Estates (Vinit) reworked the BRD around how the business actually runs: two teams, journeys, a life curve and
publication levels. Vinit's interactive artifact walks through the same model with worked scenarios.
