# CR-015: intake starts processing on the shipped vocabulary when no release is cached

| | |
|---|---|
| Raised | 2026-10-03, pilot smoke test: "Start processing" answered "no controlled-vocabulary release is cached yet" |
| Affects | intake `startProcessing` (`services/intake/src/application/mapping.ts`, `vocabulary.ts`), intake LLD §4.13 |
| Status | APPROVED 2026-10-03, auto-approved (technical, questionnaire B3); listed for the product owner's review |

## What happened
intake caches the controlled vocabulary when it applies `vocabulary.released.v1`, fetching the release from records
with its service credential. Until that succeeds, `POST /v1/uploads/{id}/start` refused with 409
`vocabulary-unavailable`. On the pilot the credential wasn't set yet, the event was dead-lettered after 5 attempts, and
no upload could be processed.

## Decision (implemented)
When no release is active for the tenant, `start` stores and activates the release shipped with the build
(`@11e/vocabulary`, currently v0.6). records seeds every tenant with exactly the same content, so the result is
identical. A later `vocabulary.released.v1` for the same version is a no-op (`known`); a newer one activates as before.
The 409 `vocabulary-unavailable` response stays in the contract but no longer occurs on this path.

## Impact
No contract, schema or event change. The service credentials are still needed for records' micromarket hierarchy and
for newer vocabulary releases; without them, localities are kept as written (the existing fallback).
